| 10 | Release | "Commit and push issue #10, then start issue #11" | Clean commit + push then continue next issue | 15 files committed with descriptive message, pushed to feature/10, then feature/11 started |

**My Reflection:**

Working with Kiro as an engineering assistant throughout Lab 2 required constant active engagement rather than passive acceptance. The most important insight was that the quality of the AI's output depended almost entirely on the specification written before implementation — the investment in specification.md, tests.md, ui-spec.md, and api-spec.md paid off by giving the agent clear, testable contracts.

The agent was strongest at mechanical tasks: translating spec tables into Prisma schemas, writing repetitive test scaffolding, and generating consistent boilerplate across many files. It was weakest at test mock isolation, where understanding async React state + Vitest's mockResolvedValue required stepping in and reasoning from first principles.

The most valuable discipline was keeping issues strictly scoped — the agent occasionally suggested future-sprint features, and the explicit "out of scope" sections in instructions.md made it easy to redirect. Overall, the AI accelerated implementation by roughly 3–4× but did not replace the need for engineering judgment on architecture decisions or test design.
