# Feature 22 requester dashboard query helpers

Feature 21 PR #50 was merged into `lab04-staging` before this Feature 22 integration began. The historical directory name is retained to preserve the existing preparation tests; these pure helpers are now used by the requester dashboard and My Tickets routes. Commit/push/PR decisions remain with the owner.

Contract: `docs/lab-04/specification.md` BR-20..24 and requester metrics; `docs/lab-04/api-spec.md` dashboard and drill-down definitions. The recent window starts at Bangkok midnight six calendar dates before the snapshot date, includes its lower bound, and excludes the snapshot instant. Estimated legacy resolutions use the existing `resolvedAt` field without excluding `resolutionTimeEstimated=true`.

`window.ts` produces frozen ISO-string snapshot metadata without mutating its input or reading the clock. `filters.ts` creates session-requester-only Prisma predicates, bounded preview query options and canonical stable sort keys. `buildRequesterDrilldown` receives only the dashboard parameter subset; the list route validates the overall dashboard query and combines legacy filters with these predicates using AND. Never allow a caller-selected requester ID or spread untrusted objects over this scope.

`server/src/routes/dashboards.ts` implements requester-only counts and two bounded safe preview lists within one RepeatableRead transaction with one snapshot time. `server/src/routes/tickets.ts` combines dashboard predicates and existing list predicates using AND; recent links retain canonical descending timestamp/ID sorts. All dashboard queries reject caller-selected identity/time-window overrides. Authentication, active-account and password-change guards are mounted at the application boundary.

The 37 pure unit tests cover date/identity/filter behavior. `requester-dashboard.db.test.ts` runs only through the disposable PostgreSQL runner and independently reconciles counts/previews with SQL, checks role/scope/error behavior and exact boundaries, verifies a repeatable snapshot during a concurrent commit, and measures requester-only performance on 1000 tickets/3000 actions. Staff dashboard performance remains a later Feature 23 check. Browser/accessibility evidence is recorded separately; backend tests do not certify UI completion.

Backend verification on 31 October 2026: `npm run test:workflow-db` passed all 54 real PostgreSQL tests (31 requester dashboard and 23 retained workflow tests), including the exact recently-resolved UI URL with `sort=resolvedAt`. The populated migration preservation check also passed in the disposable cluster. With five warmups and thirty measured requests on 1000 tickets/3000 actions, requester p50 was 9.67 ms, p95 10.41 ms and maximum JSON payload 3995 bytes. The 37 pure dashboard helper tests and server TypeScript check passed separately. No configured application database was used.
